# 032: Mods loaded from disk at run time (#28, research) (detail)

Detail of [032-run-time-mod-loading.md](032-run-time-mod-loading.md).

## 1. How a machine is known to the OS today
- **Records, filled at boot.** Stock's engine, effect and screen-page tables are relocated once into the reservation with fixed room: 256 engine, 63 effect, 256
  page slots (`tooling/stock_tables.py:47-56`), independent of the selection. The SDK fills them at the synth initializer's exit (`startup_exit.s:15`) via
  stock's registrar `0x8d50651c` (`registration_stock.cpp.in:31-46`); stock clears and refills them each run (`docs/abi-1.2.1.md:233-243`). So registration is
  already dynamic [O].
- **One indirection point per synth exists.** Stock calls only the record's `factory(index)` and the 11-entry method table it returns; it "never checks for a
  missing one" (`voice.cpp.in:1-17,222-228`). A base-held stub factory returning a silent handle can stand in until the body is loaded [I].
- **What is fixed at build:** the per-collection SDK glue. `startup.cpp.in` (generated by `tooling/startup.py:60-123`) calls each machine's `_register`,
  `_name_matches`, `_ready`, `_screen_register`, `_screen_ready` and its ID symbols directly: these are the 11 sites of record 028; `benchmark.o` (6, profiling
  only) and `sdk_companion_machines[]` (2, `project_companion_table.cpp.in`) are the rest. All become reads through a per-machine slot table. Names, labels
  (`_parameter_name`), IDs and pages must stay in the base, since menus and presets ask before any load (`presets.cpp`, `sdk_engine_installed`).
- **Own screens:** a machine's screen object lives in its BSS and registers at the GUI screen factory's exit (`abi:236`); 23 packages have a page of their own
  (15 synths, 7 effects, 1 sample). Late registration after startup is [U].
- **Content:** catalog entries in `op1_factory.json` and presets are files; with every installed machine registered, content changes only on install/remove [I].

## 2. What Open-XY code runs inside the OS, and when
- **File access:** newlib `fopen/fread/fwrite/fclose` at `0x8fed0348/05bc/0780/00ae` (`project_files.hpp:12-21`), used on the GUI role at project save and load.
  **Memory:** stock heap lock+allocate+unlock returning null instead of the fatal reporter (`sample_cache_stock.cpp:65-71`); plain stock exhaustion is fatal
  (`docs/builder.md:211-213`).
- **Control points:** synth initializer exit (both roles) and screen factory exits (GUI) at boot; `load_project`'s `deserialize` hook (`0x8d58913e`), for the
  workspace at startup and each project opened, into the *inactive* buffer before it becomes pending (`abi:850-864`); project save; catalog insertion
  (`extensions_catalog_checked`); preset scan; factory per note and render per 64-sample block (audio role); extension events on the controller path
  (`docs/extensions.md:62-66`). The core is a single BF707 (`-mcpu=bf707`, `tooling/native.py:54`); "roles" are stock tasks [I].
- **The hook to load at:** a project names each pattern's engine at pattern `+0x18` (`abi:866-870`), so the deserialize hook can list the machines a project
  needs before any note reaches them.

## 6. Shared services, runtime, and which package types can be loaded
- **Services and runtime stay in the image.** A service carries service-gated stock edits and fallbacks (`resolve_edits`, `native/mod_patch.cpp:365`; record 028
  §1); edits are patched code, not loadable data. Linking all services always costs ≤235 KB (samples alone 145 KB, mostly BSS); runtime members (divide, memset)
  are tiny. Then gated edits are always on: they must be transparent without a user [U, Q6].
- **synth, effect:** loadable (record + factory; an effect's state lives in the stock 476-byte FX slot, `api.md:56`). **sample, drum:** bodies loadable, with
  their services in the base. **Own-screen machines:** need late screen registration (§1) or their screen object kept in the base. **player:** generated tables
  and hooks (`player_table.cpp.in`, `player_hooks.s`); our layout reader rejects players today: later.
- **Extensions:** no extension patches the firmware; every site belongs to the SDK's `extensions` and `master_filter` services (`docs/extensions.md:18-21`,
  `abi:1977-1990`). An extension is reached through a generated `ExtensionEntry{id, claims, actions, Hooks*}` table
  (`sdk/platform/extension_runtime.hpp:14-18`), so its body *could* be loaded at boot behind a stub. But claims (`ext-capture`: `record_double_tap`) are
  resolved per build, and `ext-master_dj_filter` runs a processor in the master audio path, so boot only, never at project load. Both are small (capture 8 KB,
  dj filter 36 KB). **Keep extensions built in**: then changing the extension set still rebuilds the base image (only the base: no machine objects, so seconds).
  It would not, only if both services are always linked with their edits transparent when unused (Q6) and claims move to boot.

## 8. Who builds what; questions for the Open-XY maintainers
- **Open-XY:** slot-table startup independent of the collection (stub records, silent handle), the loader in the deserialize hook, late screen registration,
  services always linked, the loadable format accepted by their builder too (else `recoverFirmware`, `builder/core.mjs:1060`, rejects it).
- **XY Forever:** the per-machine loadable files at install, the on-disk layout (STORAGE: a `loaded/` folder per base), numbers for all installed machines, base
  rebuild on install of a service or extension, Mods page.
- **Q1** When does the synth initializer run again, and is the filesystem usable there? **Q2** Is there a GUI-role point where a track's engine is set from a
  catalog/preset choice, before its first factory call? **Q3** Startup order: workspace `load_project` vs synth initializer vs screen factory; can a screen
  register later? **Q4** When does stock release a machine's handles after a project switch? **Q5** Cache maintenance routine and DDR cache mode? **Q6** Are the
  gated edits of `samples`, `drums`, `extensions`, `master_filter` transparent with no user, so they can be always on? **Q7** Would they adopt a loadable
  format, or is this XY Forever-only?
