# 013: Web app design (plan item 6.1)
Research record, 2026-11-14, at plan items 1.2b-1.3, and open-xy `4718876`; no device, no network. **[F]** read from files, **[D]** design choice, **[I]** inferred, **[U]** unverified: browser facts are general knowledge as of mid-2026 and must be re-checked against current Chrome, MDN and WICG docs before 6.2b. **Question:** what the web app (a package manager that is a convenience, never a requirement) needs from the rest of the project, what earlier items must add, and how 6.2 splits.

## Decisions
1. **Web Serial on the CDC port is the app's only device door** [D]: the serial protocol covers everything, and MTP stays for ordinary file tools. WebUSB adds nothing: the OS's CDC driver holds the interface on macOS, Windows and Linux [U]; open-xy's WebUSB MTP works only on macOS, against the stock OS's vendor-class MTP [F `builder/mtp.mjs`].
2. **Chromium desktop only (Chrome, Edge, Opera)** [D]: other browsers are told to use MTP and the menu. There is no fallback transport, because the app is optional.
3. **The TS client lives here (`clients/ts/`); `scripts/protogen.py` writes its spec part (`v1.ts`) and the Python drift test checks it** [D]: the spec, the generator and the client change in one commit, and the check needs no Node. Where the web app lives is open question 1.
4. **Generated or hand-written** [D]. Generated: constants; status codes, names and classes; the command table (type, name, class, since, destructive, timeout); field tables; request/reply types; one typed encode/decode per command; events; HELLO keys; golden frames as test data. Hand-written (~600 lines): frame encoding and the resync parser (a fixed algorithm, hand-written in `usb_proto.py` too: generating it buys nothing), HELLO parsing and the `cmds` check (BigInt), transports, the call layer (one outstanding request, seq, stale replies, timeouts, parser reset, events), connect and reconnect, jobs and `progress`, chunked transfers, CRC-32, and SHA-256 by `crypto.subtle.digest` over the whole file (WebCrypto cannot hash a stream [U]; 98 MB in memory is fine on a desktop). `dev`/`test_only` commands go in a separate `dev` export that the app's UI does not use.
5. **The app requires protocol 1.1+ (`cmds` in HELLO)** [D]: a pre-v1 device gets "update XY Forever", so the client never needs the 1.0 rule. **Stack constraints** [D]: TypeScript (strict), ES modules, Vite (localhost dev server, as open-xy uses), Vitest (Node for the client, browser mode for end-to-end tests). The UI framework is left open; 6.2c uses plain DOM so that it assumes none.
6. **Tests without a device** [D]: Node tests open the simulator's TCP port directly (`node:net`). The browser reaches it through a WebSocket-to-TCP relay in the Vite dev server (6.2c), so 1.3 needs no WebSocket code. Conformance cases are data that both the Python and the TS runners execute (1.4 below).

## Browser facts (re-check before building)
- **Support [U]:** Web Serial runs in Chrome, Edge and Opera on macOS, Windows, Linux and ChromeOS (since Chrome 89). Android: reported shipped around Chrome 138 (2025), including USB serial; verify. Firefox: nothing shipped (at most a gated prototype). Safari and every iOS browser: none, and WebKit opposes it. It needs a secure context: HTTPS, or `http://localhost` / `127.0.0.1` for development. `file://`: unknown. An iframe needs `allow="serial"`. Hosting: any static HTTPS host.
- **Picker:** `navigator.serial.requestPort()` needs a click and opens Chrome's chooser; the grant is per origin [U]. Filter `{usbVendorId: 0x2367, usbProductId: 0x0021}` [D]. The service enumerates as VID `0x2367` PID `0x0021`, product "OP-XY Boot", interface classes 02 + 0A [F ioreg, a device USB log]. The stock OS uses the same PID but exposes no serial interface (MTP is vendor class 0xFF; another mode is PID `0x8021`, class 01) [F timelines, `mtp.mjs`], so the filter shows only XY Forever. HARDWARE.md's "class 06" for the OS's MTP disagrees with both sources [F]: fix it in passing.
- **Reconnect:** a restart (`device.reboot`, `menu.continue`, later `usb.mode`) removes the port. Chrome fires `disconnect`, then `connect` when the port returns, and `getPorts()` gives it back without the chooser only if the device has a USB serial number; without one, the grant ends at disconnect [U]. The macOS name `cu.usbmodem<string>1` implies a serial-number string [I]; 6.2d checks that the grant survives a reboot. The app then sends `hello` every 0.5 s, as `xyf_host.connect` does [F].
- **Open:** `port.open({baudRate})` needs a baud rate, which the device ignores [F spec]. Set `bufferSize` to 64 KiB (default 255 B [U]). Unknown [U, as in 004]: whether DTR is set on open and whether stock `cdc_write` needs it. Chrome may open the tty exclusively [U]: one tool at a time (keepalive.sh, xyf_host, the app), and the app says "close other tools".

## What `protocol/v1.json` (1.1) lacks for a generated typed client
1. Optional fields: nothing says they are all-or-none (only `usb_proto.pack`'s docstring does), so `file.read` cannot be typed as `{path} | {path, offset, length}`. Add the rule.
2. The statuses every command can return (`state` before HELLO, `unsupported`, later `busy`) are missing from the per-command `errors` lists. Add one top-level list.
3. Replies: the versions rule says tools ignore extra reply bytes, but `usb_proto.unpack` raises on them [F]. A reply that ends in `rest`/`text` can never gain fields. Write both down: the decoder is lenient on replies and strict on requests.
4. Encoding: `cstr`/`text` are "ASCII", but MTP clients make non-ASCII names. 2.4 decides: UTF-8 bytes.
5. Transport facts are prose only. Add a `transport` object (VID/PID, product string, interface classes, line settings ignored, simulator TCP port) so tools can filter from the spec.
6. Test vectors cover single frames only. Add byte streams: noise, a bad CRC followed by a good frame, a frame split at every byte, an oversize length. Minor: `values` are prose, so the TS gets literal unions (`0 | 1 | 2`); add a per-value `symbol` only if named enums are wanted. Size-dependent timeouts (`file.write_staged`, install) are prose; acceptable, because long work becomes jobs, and callers may override.
Everything else is machine-readable [F]: fixed sizes, exact request sizes, `on_error`, `destructive`, `class`, `since`, `timeout_ms`, HELLO keys and the `cmds` rule.

## Packages and the index
- **Never hosted or redistributed** [D]: official `.tfw`; any stock or decrypted `os.ldr`; firmware built from stock (open-xy builds, assembled mod sets); files from a `.tfw` (`content/`, `op1_factory.json`); keys. open-xy holds the same rule: "all firmware comes from the user's own device" [F README]. The user drops their own `.tfw`, and the device decrypts it (003).
- **Index `xyf-index/1`, static JSON** [D]. Per package: `type, id, name, version, profile, generation, needs_os`; each file's size and SHA-256; an identity hash; licence, notices, source repository@commit. Mods add kind, catalog id, tag, SDK minimum, and code/data/state bytes (memory meter). Official firmware is listed for reference only: version, `.tfw` and `os.ldr` SHA-256, content version, a link to TE's download page (010's list [F]). Dependencies stay 010's exact matches: "needs firmware 1.2.1" means `needs_os` equals the stock 1.2.1 `os.ldr` SHA-256; "needs base X" means the same `generation`. The device decides what may be installed (SAFETY's 1.2.5 rules); the index does not.
- **Hosting** [D]: the app's own origin (no CORS), files stored by SHA-256 (`packages/<sha256>`), immutable. Hosting mod packages redistributes community code, so each package carries its licence, notices and source pointer; kits with Timestretch are AGPL [F 008, README]. Until sharing and the licence are decided, the app works from files the user supplies (an open-xy kit export, package folders).
- **Fewest bytes** [D]. A `.tfw`: the browser checks the plaintext header first (magic, SKU, version, ciphertext SHA-256 [F 003]); then `storage.space`, `package.list`, the whole file into `inbox/` (the host cannot decrypt, so it cannot pick out members), and the `package.install` job. Sending only device-chosen ranges (`os.ldr` plus changed content, ~1.3 MB instead of 98 MB) waits for 2.5's throughput figure: a later minor bump that changes nothing earlier. Mods: compare `package.list` identity hashes with the index, send only the missing packages, then `mods.apply(selection)`; the device links them (008).

## Safety position
A page reaches the device only after the user picks the port for that origin [U], so the threat is a buggy or compromised app. File commands are already no worse than MTP: the same path policy refuses the brick paths (009), and destructive commands bind their target (004). The gap is running new code. Today `boot.install`, or `file.write_staged` of an `os.ldr` followed by `library.set_default` and `menu.continue`, runs new code with nobody at the device; stock needs a hand on the device to flash. So 4.8's on-device confirmation must: (a) cover every command that changes which code runs next: `boot.install`/`uninstall`, `library.set_default`/activate, `mods.apply`, and `package.install` of executable kinds; (b) be changeable only on the device; (c) not accept injected keys (`diag.key`) while it asks; (d) be visible in the protocol: HELLO key `confirm=1`, a `confirm` flag per command, status `declined` (17), timeouts that include the wait. Proposed default: on for code, off for files [D; open question 2]. Nothing is needed in the spec now; 4.8 adds this as a minor bump.

## Additions to earlier plan items (each: what breaks without it)
- **1.3:** the TCP port carries exactly the serial byte stream, for one client; `device.reboot`/`menu.continue` close the connection and listen again after a set delay; HELLO `build`/`cmds` can be set. Without this, reconnect and bitmap gating cannot be tested without the device. **1.4:** cases as data (`protocol/conformance/*.json`), run by Python and by the TS client. Without this, two suites drift apart.
- **1.2e (new; build, offline, wire unchanged):** spec gaps 1-3, 5 and 6; protogen writes `clients/ts/src/v1.ts`, covered by the drift test. Without this, the TS client is hand-written from day one.
- **2.4:** names are UTF-8; list replies carry explicit lengths (no `rest` tail). Without this, non-ASCII names break, and `file.list` can never grow.
- **4.1a/4.1c:** a package's identity is the SHA-256 of its `files.sha256` (for a single file, the file's own SHA-256); `package.list` reports it. Without this, the app must hash every file over USB to learn what the device holds.
- **4.8:** (a)-(d) of the safety position. Without them, a page can switch the protection off or press the key itself.
- **4.7:** release builds get a manifest (version, SHA-256), plus a check that a build embeds no stock bytes before any build is hosted [U]. Without this, "update XY Forever" from the app has nothing to fetch.

## Reuse from open-xy [F]
SDK and builder: MIT (Open-XY contributors); `ferret.mjs`: MIT (Bag of Waffles); kits with Timestretch: AGPL-3.0. `builder/core.mjs` (873 lines) holds the reference linker (`readObject`, `linkKit`, `patchFirmware`, `recoverFirmware`, `buildAssets`, `numberLayout`, `zipFiles`). The app can use it to relink a selection and compare it with an entry read back from the device (008's decisive check), and to recognise open-xy builds. `audition.mjs` + `sdk/browser/*` play a kit's wasm machine previews (useful for a mod browser). `ferret.mjs` turns the dev menu on and off over Web MIDI (a recovery helper). `mtp.mjs` is WebUSB MTP (macOS, stock OS). From `vite.config.mjs`: a localhost-only dev server with a file allowlist; CSP `connect-src 'self'`; `Permissions-Policy: midi=(self), usb=(self)`; static `_headers` for Cloudflare. Fetching open-xy.com's kit from another origin depends on their CORS headers [U]; linking to their site costs nothing to maintain.
