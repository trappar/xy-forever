# XY Forever TypeScript client

Talks to XY Forever's USB service (`docs/PROTOCOL.md`) from a browser (Web Serial) or Node (the
simulator's TCP port). Strict TypeScript, ES modules, no runtime dependencies.

- `src/v1.ts`: generated by `scripts/protogen.py` from `protocol/v1.json`; never edit it.
- `src/link.ts`, `src/client.ts`, `src/errors.ts`: the call layer (one request at a time, timeouts,
  cancellation, the `cmds` check, typed commands, `XyfError` with a `code`).
- `src/webserial.ts` (Chrome against the simulator; not yet on an OP-XY), `src/tcp.ts` (Node), `src/websocket.ts` (the simulator via `test/relay.ts`; `./dev`).
- Entries: `.` (browser and Node), `./node` (adds TCP), `./dev` (raw link, developer commands), `./test/*`
  (the simulators and relay, for the web app's dev server and e2e tests). All point at the TypeScript source.

Guides: [files](docs/files.md) (the file methods and their errors), [mod packages and builds](docs/mods.md)
(pushing packages, the saved inputs, building on the device).

## Build and test

```sh
pnpm install      # from the repository root (one workspace with web/): TypeScript, Vitest, @types/node (dev only)
pnpm test         # Vitest: codec, call layer, Web Serial, end to end, relay, files, mods
pnpm typecheck    # tsc (mise run web-test runs it once, after the tests)
pnpm exec vitest run test/files.spec.ts -t 'rename'   # one file, one test
node test/conformance.ts --sim 127.0.0.1:7341,7342    # the conformance cases against a running simulator
```

`mise run web-test` and CI's checks job run `pnpm test` (`mise run web-test-changed`: only the tests your changes
affect); the repository's Python suite does not. One runner, Vitest, in
Node: the Web Serial specs (`webserial`, `chooser`, `buffer`) drive the real transport through the fake
`navigator.serial` of `test/fake-serial.ts` (Chrome's receive buffer, the chooser, granted ports); the app in Chrome
with the same fake is `web/e2e/install-sim.e2e.ts`. The web app driven against the OP-XY itself:
`web/scripts/device-browser-test.ts` ([web testing](../../web/docs/testing.md)).

The run starts its own simulators at once (`python -m xy_forever.sim` from the project venv, however Vitest is
started; `--port 0`: its ports are ones the system picks, read from its output, so parallel runs never race for one;
state under the private sessions folder; `XYF_TS_SIM_STATE`, `XYF_KEEP_SIM=1`). Without the private stock files or clang++
(CI) it skips the simulator tests with the reason; a missing venv or a simulator that does not start fails the run. Their transport pauses on the
simulator's clock (`simOpener`, `Transport.pause`), so polls take no host time. Budgets, enforced on CPU time (the test's
process and its simulator's: `test/cpu.ts`): each test's and the sum of the run's, about twice an unloaded run's and
scaled on slower hardware (`test/run-budget.ts`: over one fails the run and names the test); wall time is only
reported. Vitest's time-outs and the run's hang bound, on wall time, stay the outer limit. Node 26 (pinned in `mise.toml`).

## Use

```ts
import { Client, decodeScreen, isXyfError } from 'xy-forever-client/node';   // browser: 'xy-forever-client'
import { tcpOpener } from 'xy-forever-client/node';     // browser: connectWebSerial() from a click (granted port, else the chooser)

const client = await Client.connect(tcpOpener('127.0.0.1:7341'));   // hello; pre-1.1: update_required
console.log(client.info.build, client.info.limits);
const version = new TextDecoder().decode(await client.readFile('/yaffs2/firmware.version'));
await client.writeFile('/yaffs2/xy-forever/notes.txt', data, { onProgress: (done, total) => {} });  // ask the user first
const { rgba } = decodeScreen(await client.screenshot());
try { await client.reboot(); await client.reconnect(); } catch (e) { if (isXyfError(e, 'timeout')) {} }
```

The call layer's time-outs and pauses: a call's `timeoutMs`, `Client.pause` (wall time on a real device, device time on
the simulator). A read-only command (`file.read`, `file.list`, `diag.status`, ...) whose
reply does not come within `RESEND_MS` (3 s) is sent once more (#306); nothing that changes the device is resent. The rest: [files](docs/files.md), [mod packages and builds](docs/mods.md).
